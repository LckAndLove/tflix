# 字幕与音频不同步：链路排查与修复设计

日期：2026-10-20。本文区分代码/接口已证实的问题与尚未测量的音轨同步误差，不把显示字幕或设置偏移视为同步验收。

## 结论

不能给所有内容统一加减秒数。当前字幕选择没有绑定实际视频版本；部分候选是分盘字幕，部分发行版本/帧率不同；外部播放器还有异步载入后偏移未应用的竞态。可靠方案必须同时解决候选匹配、加载生命周期、媒体时间轴和验证，而不是叠加偏移补丁。

## 实际链路

1. `stream/index.html` 以 TMDB ID/季/集选取第三方 iframe。
2. Tauri 注入 `player_compat.js`，在 macOS CineSrc 中优先原生 HLS；`player_bridge.html` 提供 HTTP Referer。二者没有做字幕时间校正。
3. CineSrc 自身解析视频源及内置字幕，并通过 `/api/subtitles/search` 搜索外挂字幕；失败后请求 `subs.bright67.online/search`。
4. 本地 `subtitle_compat.js` 拦截字幕文件下载。有效 SRT/VTT 原样通过，ASS/SSA 转换为 VTT；原文件坏掉时，再从同作品/集、同语言候选中找首个能解析的文件。
5. CineSrc 将文件变成 Blob URL，异步创建 `<track data-custom-subtitle>`。字幕选择和偏移由其 React 状态管理。
6. 原生 TextTrack 根据媒体时间决定 activeCues，CineSrc 的字幕覆盖层监听 cuechange 后渲染。`subtitle_layout.js` 只改变位置，不改变时间。

## 已确认问题与证据

### A. 替代字幕没有校验视频发行版本

`subtitle_compat.js` 的 fallback 只检查 language，并使用最先成功解析的候选。没有检查 release、分盘编号、实际片源版本或字幕覆盖范围。

《时光代理人》S1E1 的原英语文件 id=1957839167 返回数据库错误文本，兼容逻辑可替换为 id=1960490883；两者的 release 不同。备用版首句为 00:44.950，而另一份 CR 法语版本对应首句为 00:38.860。这里只证明发行时间轴不一致，不能据此推导整集都应减固定六秒。

### B. 《教父》搜索结果是分盘字幕，并混有不同帧率

实际读取：

- `https://subs.bright67.online/search?id=238`
- `https://subs.bright67.online/search?id=238&language=en`

后一请求仍只返回下面四份英文候选；增加语言过滤没有找出完整片版本。

安装版媒体界面显示总长 2:55:34。文件名和 discNumber 已证明候选是分盘资源，不应当自动当作完整电影字幕。接口给出的 `syncConfidence=likely`、`matchedBy=imdbid` 没有证明其匹配当前视频。没有读取实际视频帧率，不能把字幕 fps 字段当作视频 fps。

### C. 外部播放器存在异步加载与偏移应用竞态

当前线上入口：`https://cinesrc.st/_next/static/chunks/a57434a6c025b90c.js`

2026-10-20 下载脚本，SHA-256 前缀 `69827ea472159c07`，与此前缓存一致。

选字幕时先更新 selectedSubtitleId，随后 await 下载，再创建 track。偏移 effect 仅依赖 `[offset, selectedSubtitleId, playerRef]`，遍历当时已存在的 cues；track load 回调只保存原始时间，没有重新应用偏移。选择状态改变时新文件尚未加载，因此 effect 可以执行在空 cues 上。加载完成后上述依赖不变，界面偏移值与实际 cue 时间不一致。

用实际 effect 原代码做最小复现：配置 offset=-6，下载前执行 effect；下载后加入 startTime=100 的 cue，load 回调缓存原值。实际仍为 100，并非 94；手动再次执行 effect 才变为 94。

这是确定的代码竞态，但尚未证明用户当前每一次失同步都是由它触发。

### D. 字幕选择缓存不包含实际视频源身份

外部播放器使用 `cinesrc-subtitle-selection:<tmdb>:<season|movie>:<episode>` 存储选择。相同作品切换内部视频源或不同发行版时，选择可以继续复用，缓存键没有对应的视频版本/文件指纹。

### E. 已排除与未排除的范围

- ASS 小数秒转换如 `1.25 → 1.250`、`44.95 → 44.950` 保持秒值，不是在转换时额外增加六秒。
- 字幕位置 CSS 不改变 cue 起止时间。
- 当前显示链路依赖原生 activeCues，而非另外用墙钟计时显示；不能把网络下载耗时直接当作字幕延迟加到时间轴。
- 尚未抓取实际片源的首段时间轴、音频 PTS、discontinuity 与字幕映射，不能宣布原生 HLS 完全没有时间原点问题。
- 尚未对当前音轨进行识别/强制对齐；未实听验证具体台词的误差，不能宣称当前字幕已经同步。

## 可靠修复方法

### 1. 先切断错误匹配

- 删除“原文件失败后任取同语言文件”的静默替换；同一文件的备用下载地址可以重试，不同文件必须重新匹配并改变实际选择身份。
- 优先使用随当前视频发布的内置字幕轨；也应记录其对应版本，并对多音轨配音差异保持区分。
- 外挂字幕记录 release、来源、文件名、分盘、fps、起止范围、内容哈希；实际视频记录标题/集数、视频版本身份、时长、可获取的帧率和音轨。
- CD1/CD2 不得自动套在完整电影上。不能以“CD1 最后一句时间”推断 CD2 起点并拼接，真正分盘边界需有可靠数据。
- 只有作品 ID 的匹配不能标成“已同步”。没有匹配候选时明确显示没有匹配字幕，而不是给出貌似可用的错版字幕。
- 独立查询具体语言与发行版本可改善候选质量，但此次英文查询仍无完整片文件，因此需要可靠的其他字幕来源或同版字幕文件。

### 2. 由本地统一管理字幕生命周期

长期实现应提供明确的字幕控制器，不依赖外部 minified React 内部状态作为可靠同步机制：

- 每次视频源/字幕切换分配 generation token，取消旧请求，忽略过期 load/cuechange 回调。
- 解析结束、track load 成功之后才应用同步模型，保存不可变的原始 cues；以后总从原始值计算，不能在已经变换的 cue 上累加。
- 统一管理选择、加载状态、同步模型和渲染轨，避免一层改 VTT、一层再平移 TextTrack。
- 内置轨和外挂轨均使用当前媒体时间轴；暂停、快进、倍速、缓冲、全屏不另建字幕计时器。
- 修复异步竞态是必要措施，但不能让错误发行版自动变成正确字幕。

### 3. 根据证据选择同步模型

- 有相同版本字幕：不做推测性校正，先验证原始时间。
- 有内容锚点且误差恒定：允许使用经过测量的平移；它只是模型之一，不是全局默认值。
- 帧率/速度差：有足够锚点时拟合 `videoTime = a * subtitleTime + b`；不能仅凭标称 23.98/25 猜比例，因为字幕可能已按发行版校准。
- 不同剪辑/片头/广告插入：采用有内容锚点的分段单调映射，或更换同版字幕。全局平移/缩放无法修复所有分段差异。
- 若使用音频内容对齐，必须先取得当前真实音轨并识别有效语音区间/文本锚点；给出置信度和拒绝条件。不能只用静音、字幕行数或第一句时间声称自动对齐成功。
- HLS 分段 WebVTT 按 X-TIMESTAMP-MAP/媒体 PTS 映射处理；完整外挂 VTT 与分段 VTT 不可混为同一种时间原点。

### 4. 缓存与验证

- 同步结果以 视频版本身份 + 音轨 + 字幕内容哈希 为键；换源、换音轨、换文件必须重新验证，不能全片名/整季共用一个偏移。
- 可用诊断数据至少包括当前源身份、音轨、video.currentTime、seekable 起点、字幕 ID/hash、原始和生效 cue 时间、变换模型及其来源；不得记录带访问令牌的完整签名 URL。
- 自动化用固定样本验证零偏移、固定偏移、线性漂移、插片分段、分盘字幕误匹配和异步加载/切换竞态。
- 实际验收应覆盖片头、中段、接近结尾，并在暂停/继续、快进、倍速、换源与重开后重复检查。
- 将“播放状态正常”“字幕加载成功”“内容同步验证通过”分开；本次前两者的通过不能替代第三者。

## 建议实施顺序

1. 停止错版自动替换；加入分盘识别、实际文件身份和可追溯的匹配状态。
2. 建立本地字幕生命周期与诊断，消除 load 后偏移未应用及旧结果串入新源的问题。
3. 找到同版完整片字幕并验证；有必要时再接入带置信度的内容对齐。
4. 完成头/中/尾与操作后的内容同步验证，再发布“字幕同步已修复”的结论。

## 已实施与实际验证（2026-10-20）

已将 CineSrc 外挂字幕改为 TFLIX 本地控制：`subtitle_compat.js` 仅下载指定文件、保留发行元数据并排除分盘；`subtitle_session.js` 用取消信号与 generation token 管理下载/原生解析；`subtitle_controller.js` 在原生 TextTrack 加载成功后启用轨道，以 `activeCues` 渲染。没有添加固定偏移、帧率猜测或独立字幕计时器。外部播放器的外挂自动目录被关闭，片源内置轨仍保留。只记住语言，不跨源恢复旧文件。加载状态和目录状态分别显示。
