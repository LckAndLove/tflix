# 桌面原生直开播放（2026-10-23）

## 结构

桌面端：本地选集/进度控制器 → Rust 创建专用 WebviewWindow → 直接打开共享 adapter 的播放器 URL。视频源自己的内部 iframe 仍由源站管理，TFLIX 不增加 iframe 或本地 HTTP 中转页。

网页端和 Android 继续使用原有 iframe。六个源的默认顺序、手动覆盖、单集偏好和电影/剧集 URL 保持一致。没有探测、就绪超时、失败遮罩或自动切源。

## 控制与存储

- 新窗口注入隔离在 Shadow DOM 内的返回、选集、源名称菜单和语言按钮。视频、清晰度、音量和全屏由源站播放器处理。
- Ekko 继续注入现有字幕选择和字幕同步面板。
- 本地控制器保存源偏好、历史和进度。原生窗口仅回传动作与媒体时间，不回传媒体地址。
- 每次手动换源/换集创建新的会话，旧窗口消息被忽略；同片同源续播仍要求时长匹配。
- 关闭或返回会恢复原主窗口。重复启动应用会聚焦当前播放窗口。

## 共用配置与权限

`stream/source-config.js` 中带标记的纯 JSON 数据同时供 JavaScript adapter、Rust URL 校验和构建时权限生成器读取。修改源时维护这一份数据即可。URL 校验要求电影/剧集/季/集及原有参数完全对应，仅允许额外的起播时间参数。

源窗口只有 `native_player_event` 一个自定义 IPC 权限；不能检查/安装更新、打开系统 URL，不能创建播放器窗口或请求执行脚本。本地控制器的命令不授予远程源。事件只接受白名单动作、有限且合理的时间数值，不接受脚本或播放失败指令。

## 验证记录

- 原生 Ekko：Mac 上《时光代理人》S1E3 曾有画面并播放；新版实测同一集源站多次返回内部源搜索或“视频不可用”，表现不稳定。全屏进出和返回详情已验证。
- 六源直接打开：Mac 上逐个选择，确认播放器窗口顶层分别加载到 cinesrc.st、moviesapi.to、vidfast.vc、vidsrc.sh、vidlink.pro 和 vixsrc.to；控制栏与源名同步更新。Bard 页面加载出 vidspark 内层页面。Naafiri/Ryze 的样本停在源站加载提示；Xayah 的内层页面显示播放控件，点击后变成 about:blank；Rakan 样本返回源站 HTTP 404。以上结果证明入口不再经过 TFLIX iframe，但不能证明每个样本都能播放。
- 控制栏：选集面板、季列表、Escape 关闭后焦点恢复、语言入口、六源手动菜单已实机检查。Lupin S1E1 → S1E2 的地址及标题同步此前已验证。
- 字幕：原生注入的 Ekko 字幕面板正常显示；《登峰传奇：丹增诺盖》显示同版本未验证的中文外挂字幕。字幕偏移控件在没有可用轨道时禁用，不能据此证明字幕与音轨同步。
- 进度：播放监控将影片进度报告为 21:22 / 2:05:33；再次加载过程中界面曾显示 0:00，之后媒体重新加载。现有代码测试通过，但新版的实际续播是否稳定仍未确认。
- 自动化：103 项 Node 测试通过；4 项 Rust 测试通过；`cargo check` 与严格 Clippy 检查通过。
- 六源电影/剧集的 12 条 URL 均与改造前的固定样本完全一致；Rust 接受这些 URL 及各源合法起播参数，并拒绝多余参数。
- Windows/Linux 实机结果未验证。不能把入口返回成功当成视频播放成功。

## 已知限制

直开只能消除 TFLIX 外层 iframe 的影响，无法修复源站资源缺失、网络、解码和源站内部嵌入问题。实测源站结果差异明显，Xayah 点播放后进入 about:blank；需要确认该源的弹窗/内部导航限制后，才能判断它能否在 TFLIX 内可靠工作。源站导航、Cookie 和内部播放器会变化。首屏取决于源站响应；即使页面未完成加载，也可以用窗口关闭按钮返回。
